# 两套系统准备说明

## 1. 硬件与软件

建议使用：

- x86-64 Linux，Ubuntu 22.04 或 24.04；
- 16 GiB 内存；
- 至少 25 GiB 可用 SSD 空间；
- GCC/G++ 9 或更高版本；
- Python 3.8 或更高版本。

安装课程所需公共依赖：

```bash
sudo apt update
sudo apt install -y build-essential cmake git curl zstd \
  libaio-dev libgoogle-perftools-dev libopenblas-dev libeigen3-dev
```

课程统一使用 Linux AIO backend。这样不依赖容器或虚拟机是否允许 io_uring，也避免两套系统因 I/O backend 不同而无法比较。无需安装 SPDK、MKL、gRPC、RocksDB 或 Python 接口依赖。

固定源码版本记录在 `adapters/versions.json`。源码默认放在被 Git 忽略的 `systems/`，构建结果、数据和索引也不会进入课程仓库。两套适配器的 `doctor` 会同时检查固定 Commit、二进制、`Release` 构建和 AIO 选项；任一检查不匹配都会返回错误，Debug 和 Formal 一键脚本将立即停止。

## 2. 自动准备 PipeANN-Filter

源码仓库：<https://github.com/thustorage/PipeANN>

```bash
bash scripts/prepare_pipeann.sh
```

该脚本会：

1. 克隆或检查 `systems/PipeANN`；
2. 切换到课程固定 Commit；
3. 使用 `Release + AIO + tcmalloc` 编译；
4. 生成适配器所需的两个二进制；
5. 数据已下载时自动运行 `doctor`。

使用其他源码目录：

```bash
bash scripts/prepare_pipeann.sh /path/to/PipeANN
```

预期二进制：

```text
<repo>/build/tests/build_disk_index_filtered
<repo>/build/tests/search_disk_index_filtered
```

手动检查：

```bash
python3 adapters/pipeann_adapter.py doctor \
  --repo "$PWD/systems/PipeANN" \
  --dataset-root "$PWD/datasets/yfcc_course_v1" \
  --tier debug
```

## 3. 自动准备 GateANN

源码仓库：<https://github.com/GyuyeongKim/GateANN-public>

```bash
bash scripts/prepare_gateann.sh
```

除固定 Commit 与 AIO 编译外，脚本还会应用 `patches/gateann_aio_compat.patch`。上游固定提交中有一处 `cb.data` 数组访问笔误；补丁将其改为 `cb[j].data`。这是一行编译兼容修复，不改变 GateANN 算法、数据布局或预构建索引格式。重复运行准备脚本不会重复应用补丁。

使用其他源码目录：

```bash
bash scripts/prepare_gateann.sh /path/to/GateANN-public
```

预期二进制：

```text
<repo>/build/tests/build_disk_index
<repo>/build/tests/search_disk_index_yfcc
```

手动检查：

```bash
python3 adapters/gateann_adapter.py doctor \
  --repo "$PWD/systems/GateANN-public" \
  --dataset-root "$PWD/datasets/yfcc_course_v1" \
  --tier debug
```

GateANN 正式索引约 486 MiB，查询进程通常远低于 1 GiB RSS；课程建议 16 GiB 是为了给编译、Debug 索引构建、操作系统缓存和其他进程留余量。Formal 索引由课程提供，因此不需要学生承担其构建内存。

GateANN 第一次查询 Debug 索引时会在索引目录生成约 13 MiB 的 `yfcc.full_adj.R32`。这是 Graph Tunneling 使用的邻接结构，属于正常行为；后续查询会直接加载它。

### Debug 构建失败后重试

索引会先构建在同一磁盘上的临时目录中，只有构建程序正常结束且生成主索引文件后，才会切换到正式索引目录。因此，构建中断或失败后可以直接重新执行原构建命令，不需要手动删除半成品。

每次构建的命令和日志分别保存在：

```text
course_runs/builds/<system>/<tier>/<attempt-id>/
```

失败产生的半成品会保留在以下隐藏目录中，供排错使用，但后续查询和重试不会使用它：

```text
course_runs/indices/<system>/.<tier>.failed-<attempt-id>/
```

确认不再需要排错且磁盘空间紧张时，可以手动删除对应的 `.failed-*` 目录。若旧版适配器曾直接在正式目录留下不完整索引，新版会先将其移动到 `.incomplete-*` 目录，再开始一次全新的构建。

## 4. 下载预构建正式索引

```bash
bash scripts/download_indexes.sh
bash scripts/check_indexes.sh
```

下载内容：

| 系统 | 压缩包约 | 解压后约 | 安装目录 |
|---|---:|---:|---|
| PipeANN-Filter | 1.05 GiB | 8.43 GiB | `course_runs/indices/pipeann/formal_1000000/` |
| GateANN | 401 MiB | 486 MiB | `course_runs/indices/gateann/formal_1000000/` |

下载脚本校验压缩包 SHA-256，解压后再逐文件校验，并检查索引对应的系统、数据版本和 Tier。已经存在的目标目录不会被覆盖；脚本会直接验证它。下载可通过 `curl --continue-at -` 续传。

下载目录和 URL 可通过环境变量覆盖，默认值见 `config/indexes.env`。例如将索引放到另一块 SSD：

```bash
FVS_INDEX_ROOT=/mnt/ssd/course_runs/indices bash scripts/download_indexes.sh
```

此时正式实验还需要使用同一 `run_root`。最简单的方式是把整个 `course_runs` 放到该 SSD 并将其作为正式脚本第三个参数：

```bash
bash scripts/run_formal_experiments.sh \
  "$PWD/systems/PipeANN" \
  "$PWD/systems/GateANN-public" \
  /mnt/ssd/course_runs
```

## 5. 运行前排错

### `doctor` 报 Commit 不一致

Commit 不一致属于硬错误，不能继续 Debug 或 Formal 实验。准备脚本只会在源码没有本地修改时切换 Commit，以免覆盖个人工作。先用 `git -C <repo> status` 检查，再重新运行对应的准备脚本。GateANN 应只有课程补丁造成的一处已知工作区修改；该补丁不会改变 HEAD Commit，因此能够通过版本检查。

### 找不到 `tcmalloc`

确认安装：

```bash
sudo apt install libgoogle-perftools-dev
```

### 找不到 `aio` 或 `libaio.h`

确认安装：

```bash
sudo apt install libaio-dev
```

### 找不到 BLAS

确认安装：

```bash
sudo apt install libopenblas-dev
```

### 索引或数据校验失败

不要继续正式测试。保留错误输出，确认磁盘空间和下载完整性。脚本不会覆盖已有解压目录；若需要重新下载或解压，请先确认目录中没有个人数据，再手动移走对应目录。

## 6. 可选扩展：Filtered-DiskANN

仓库保留 `adapters/filtered_diskann_adapter.py`，对应 [DiskANN cpp_main 分支](https://github.com/microsoft/DiskANN/tree/cpp_main)。它不属于必做范围，课程也不提供正式预构建索引。只有在两套必做系统和报告已完成后再考虑扩展。
